## 3. 見つかった問題点と対処

### 3.1 減衰（×0.7）と停止ルールが混ざっている（最重要）

2回目のループで加わった候補の総合点は最大でも `Q×P×0.7 ≤ 0.7` です。一方、1回目の上位5件の最低点は 0.85 でした。
つまり**2回目の候補は、LLMが何と答えても上位5件に入れません。** 「上位の顔ぶれが変わらなくなったら止める」というルールは、この条件では必ず2回目で発火します。デモが「2回目で打ち切り」になったのはLLMの知識の結果ではなく、定数の帰結です。

| 減衰 | 実行された回数 | 停止理由 | 上位5に入った2回目の候補 |
|---|---|---|---|
| 0.5 | 2 | 上位5件が不変 | ─ |
| 0.7（デモ） | 2 | 上位5件が不変 | ─ |
| 0.9 | 3 | 新候補なし | CSF2RA |
| 1.0 | 3 | 新候補なし | CSF2RA |

**対処案**：減衰を総合点ではなく近さ（P）だけに掛ける、または停止判定を「回ごとの上位k」で行う。コードでは `ScoringRules.round_damping` を変えて試せます。

### 3.2 関係の網の近さ N の「起点」が未定義

デモでは「直接の相手なら1.0、2段先なら0.5」とだけ決めていました。MYD88 は IRAK4（2段先）の上流なので、
起点を「最初の種」とすれば 3段以上（N=0）、「1回目で見つかった候補」とすれば直接（N=1.0 → 0.8×1.0=0.8）です。
会話記録の P=0.7 は前者の読みでのみ一致します。コードでは**「既知（種＋検証で既知になった遺伝子）からの段数」**と定義しました。

### 3.3 5段階の確信度では同点が構造的に起きる

5段階×5問では Q は21通りの値しか取れません。実際、0.90 に3遺伝子が並びました。
対戦比較が必要になった理由はここにあります。TxGemma の実確率（連続値）を使えばこの同点は減りますが、
「はい」確率が 0.99 と 0.999 のように上に張り付く場合は log-odds に変換した方が差が見えます（統合モデルの回で述べた点と同じ）。

### 3.4 設計（第4章）とデモのルール（ステップ0）の不一致

設計では「3種類の近さのうち2種類以上で近いものを優先する」とありましたが、デモのルールは `max(M, 0.8N, 0.6V)` だけで、
2種類以上の加点は入っていません。オプション `multi_evidence_bonus` として実装しました（既定は0）。0.15 を加えると IRAK4 が CSF2RA を上回る程度で、上位5件は変わりません。

### 3.5 ルール定数への感度（まとめ）

| 変えた定数 | 範囲 | 上位5の重なり | Kendall τ（最小） |
|---|---|---|---|
| 網の重み 0.8 | 0.6〜1.0 | 5/5 | 1.00 |
| 地図の重み 0.6 | 0.4〜0.8 | 5/5 | 0.96 |
| 隣の段階 0.7 | 0.5〜0.9 | 5/5 | 0.91 |
| 減衰 0.7 | 0.5〜1.0 | 4/5 | 0.73 |
| 2種類加点 | 0.1〜0.2 | 5/5 | 0.96 |

全表は `docs/sensitivity.md`。上位は定数にほとんど依存しません。裏を返すと、**上位の並びは質問の答え（ほぼ全部 1.0）で決まっており、質問の側に識別力がない**ことを示しています。CSF2（第3相で失敗）が最上位に来た原因もここです。

### 3.6 提案されていた「ヒト遺伝学の質問（Q6）」の効果

会話記録の最後で提案された Q6 を実装し、Claude の判定値（未検証・後知恵あり）を入れて動かすと、
順位は `TYK2 > CSF2 > BTK > TNFRSF1A > …` となり、RA の GWAS で強い支持がある TYK2 が CSF2 を上回りました。
設計の意図どおりに動くことの確認であって、性能の証拠ではありません。

## 4. llama.cpp 経路の確認（前回のエラーの後始末）

前回の会話は `logits_all=True` のエラーで終わっていました。今回の `LlamaCppBackend` では：

- `logits_all=False` で読み込み、`eval()` の後に最後の行の logits を読みます。`logits_all=True` は不要で、しかも Gemma の語彙 26万 × 文脈 2048 × 4バイト ≈ 2.1GB のバッファを確保するため、メモリ不足の原因になります。
- 「Yes」「 Yes」「yes」は別トークンなので、1トークンで表せる綴りを全部足し合わせて `p_yes = ΣYes / (ΣYes + ΣNo)` とします。
- 選択肢の順（Yes or No / No or Yes）を入れ替えた2通り × 言い換え3通り = 6回の平均を1問の答えにします。

ランダム重みの極小モデル（`scripts/make_tiny_gguf.py`）でこの経路が例外なく動くことを確認しました。ただし出力値は無意味です。

### 4.1 guidance 方式（お使いの `option_logprobs`）の確認

guidance 0.3.1 で、`select` の後に `state._trace_nodes` の `TokenOutput.top_k` から制約前の確率が読めることを、極小 GGUF で確認しました。注意点は2つです。

- `LlamaCpp(model, echo=True, top_k=TOP_K)` としないと top_k が記録されません（ソース上 `enable_top_k=echo`）。`echo=False` にすると top_k が空になり、お使いの関数は空の辞書を返します。
- top_k に選択肢が入らなかった場合、お使いの版は黙ってその選択肢を落とします。`GuidanceBackend` とノートブックでは、top_k の最小確率を上限値として代用し `missing` に記録する形に変えました。`missing` が出たら `TOP_K` を増やしてください。

### 4.2 実機（Ollama gemma3:4b-it-qat）での最初の結果と対処（2026-09-23）

set100 を Ollama の gemma3:4b-it-qat で採点したところ、全遺伝子が `p_yes = 0.944`、`frac = 1.0` になりました。原因は2つです。

1. その版の Ollama は `/v1/completions` で logprobs を返さず、代用のサンプリング（温度 1.0 × 8 回）に落ちていた。0.944 = (8+0.5)/(8+1) で、8 回すべて Yes だった印です。確率は読めていません。
2. 小型の指示調整モデルは「もっともらしいか？」に迎合して Yes に寄る。嗅覚受容体（OR8U8）まで Yes でした。

対処として、ノートブック 02 に次を入れました。
- Ollama の `/api/generate` でも logprobs を試し、読込時に「対応／非対応」を表示する。
- 確率が読めないときの主スコアを **0〜9 の評点**（サンプリング平均）に変える。確率が読めるときは各数字の確率からの期待値。
- `STRICT_PROMPT`（大半の遺伝子は標的ではない、の前置き）と、対照疾患による補正（`USE_CONTROLS`）。
- **較正チェック**：嗅覚受容体・無関係な遺伝子・確立した標的の3つでスコアの差が 0.1 未満なら警告する。本番の前に必ず見る。

根本的には、確率が読める経路（`~/llm/models` の GGUF ＋ guidance）で 9B 級以上のモデルを使うのが本筋です。

## 5. 次にやること（お手元のMacで）

1. `pip install llama-cpp-python guidance` の後、`python scripts/run_txgemma.py --model <TxGemmaのGGUF> --mode compare`。
   13遺伝子 × 5問 × 6回 = 390回の forward pass ＋検証質問で、9B Q6_K なら M系Macで10〜20分の見込みです（要実測）。
   出力 `outputs/txgemma_compare.csv` に Claude の確信度と TxGemma の p_yes が並びます。相関が低い質問（例：副作用 Q5）は質問文の見直し候補です。
2. `--mode loop` で拡張もLLMに任せると、18遺伝子以外（CD28、TNFRSF1B、IL23A など）が出てきます。
   遺伝子記号の誤認を防ぐため、PCに保存している HGNC の記号リストを `known_symbols` として渡してください（この環境からは確認できませんでした）。
3. §3.1 の対処（減衰の掛け方）を決めてから、時間で区切るテストへ進んでください。ルールを試験結果を見て変えるのは「人が学習している」のと同じなので、順番が大事です。

## 6. 良い面と限界

**良い面**
- 仕組み全体が約600行の純粋なPythonで、LLMを差し替えても壊れません。
- 記録再生バックエンドのおかげで、答えの記録さえあれば誰でも同じ結果を再現できます。
- 「答えのない質問で黙って既定値を返さない」設計（`KeyError`）なので、再現漏れが隠れません。

**限界**
- ここで示したのは「手順が設計どおり動く」ことまでで、「TxGemma でも同じ順位になる」「新しい標的を当てられる」ことは未検証です。
- 拡張の質は LLM が遺伝子リストを正しく書けるかに依存します。9B級のモデルでは記号の誤りが出る前提で、記号リストによる照合が必要です。
- 研究の少ない遺伝子は、どの近さでも見つけにくいという根本の限界は変わりません。
