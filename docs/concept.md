# 標的探索のコンセプト（整理版）

作成日: 2026-09-21。これまでの会話（RAG案 → 知識採点案 → 統合モデル案 → 学習なしループ案 → 小規模デモ → コード化と検証 → 遺伝子セット作成）を通した、現時点での考え方をまとめ直したものです。

## 1. 一言でいうと

**AI が読んで覚えている生物学の知識だけを使い、病気の標的になりうる遺伝子を全遺伝子の中から順位付けする。** 調べる操作（検索・外部問い合わせ）はしない。学習もしない。代わりに「聞き方」と「確かめ方」と「測り方」を先に固定する。

中学生向けのたとえ：教科書をすべて暗記した生徒に、資料持ち込み禁止で「この病気に効きそうな遺伝子はどれか」を答えさせる。ただし一問一答では当て推量になるので、小さな質問に分けて何度も聞き、逆からも聞き、二人を比べさせ、反対意見も言わせる。採点表は試験の前に決めて貼り出しておく。

## 2. 何を目指し、何を目指さないか

| 目指す | 目指さない |
|---|---|
| 既知の標的を高い正解率で上位に置く（リストA） | 文献検索の代わり |
| 直接の報告がなくても、しくみ・関係・機能の近さから候補を出す（リストB） | 研究がほとんど無い遺伝子の発見（知識が無いものは出ない） |
| 全遺伝子を同じ物差しで並べる | 「効くかどうか」の証明（それは実験の仕事） |
| 秘密を守る（外部通信ゼロ） | 最新知見の反映（AI の知識の締め切りで止まる） |

## 3. 仕組みの3層

### 3.1 知識の引き出し方（1つの遺伝子について）
- **小さな質問に分ける**：組織で働くか／しくみの鎖のどの段階か／止めると良くなる向きか／薬が結合しやすい種類か／重い副作用があるか（＋ヒト遺伝学の証拠があるか）。
- **「はい」の確率で受け取る**：文章を書かせず、次のトークンの確率から Yes/No を読む（guidance の `select` ＋ 制約前 top_k）。1問 = 1回の forward pass。
- **癖を消す**：言い換え3通り × 選択肢の順2通り = 6回の平均。有名度は無関係な対照疾患での「はい」平均を引いて補正。
- **逆から確かめる**：「その標的の承認薬は？」→「その薬の結合相手は？」、「その段階で働く遺伝子は？」。矛盾すれば別枠。
- **比べさせる・反対させる**：上位は2つずつ対戦比較（左右入れ替え）、上位3件に反論役。

### 3.2 近さ3種（既知の標的からどれだけ近いか）
| 近さ | 測り方 | たとえ | 弱点 |
|---|---|---|---|
| M しくみ（MoA） | 病気の鎖の同じ段階・同じ向きか、隣の段階か | 同じ仕事 | 鎖が間違うと全部ずれる（専門家の点検が要） |
| N 関係の網 | 既知からの段数（直接の相手 1、その先 2） | 知り合いの知り合い | AI が挙げる相手の誤り |
| V 地図（ベクトル） | 説明文の埋め込みの角度 | 住所が近い | 兄弟遺伝子ばかり出る |

**「V は遠いが M は近い」遺伝子が最も面白い。** 見た目は違うのに同じ流れを止められる候補で、有名度の偏りを受けにくい（デモでは RANKL がここから出た）。

### 3.3 先に固定した統合ルールと4分類
```
Q = 質問の「はい」確率の平均（副作用は 1−p）
P = max(M, 0.8N, 0.6V)
総合 = Q × P × 減衰^(回数−1)     逆向き・矛盾 → 別枠
```
出力は **既知 / しくみが近い / 地図が近い / 組み合わせ / 別枠** に分け、すべてに「種 → 見つけ方 → 候補、段階、向き、検証結果」の根拠の鎖を付ける。

ループ（種 → 広げる → 確かめる → 分ける）は最大3回。検証を通った候補を次の種にする。

## 4. 測り方（今回作った遺伝子セットの使い方）

`data/genes/` に RA と統合失調症の遺伝子セットを置いた。各セットは **正解（承認薬の標的）・可能性（GWAS・エクソーム・CNV・臨床試験・生物学）・ランダム** の3種を混ぜ、順序をシャッフルしてある（並び順から答えが漏れないため）。

| セット | 内容 | 用途 |
|---|---|---|
| set100 | 正解 + 可能性 + ランダムで 100 | Mac での試作。1モデル・1病気で 100 × 5問 × 6回 = 3,000 forward pass |
| set1000 | 同 1000（set100 を含む） | サーバでの本番。全遺伝子（約19,000）に広げる前の中間規模 |
| hgnc_protein_coding | 全タンパク質コード遺伝子 19,297 | 全遺伝子採点と、AI の答えの記号照合（known_symbols） |

測る指標は3つ。
1. **既知の再現**：正解遺伝子が上位に来るか。上位k件中の正解数、AUC、平均適合率。ランダム選択が基準線（set100 なら上位10件に正解は平均 1.5 件）。
2. **可能性遺伝子の位置**：可能性遺伝子がランダム遺伝子より上に来るか。ここが「直接の報告がなくても拾えるか」の代理指標。
3. **偏りの補正効果**：有名度補正の有無で 1・2 がどう変わるか。

そして最後に **時間で区切るテスト**：AI の知識の締め切り後に初めて報告された関係を正解にして、上位に置けるかを測る。ルールはこのテストの前に固定し、結果を見て直さない。

## 5. 分かっている限界（正直な注意点）

- **後知恵**：デモの答えは Claude の判定で、臨床結果を知っている。性能は TxGemma などで測り直す。
- **質問の識別力**：デモでは答えが 1.0 ばかりで、CSF2（第3相失敗）が最上位になった。「しくみとして筋が通るか」しか測れておらず、「患者で効くか」は測れていない。ヒト遺伝学の質問（Q6）を足すと TYK2 が上がる。
- **減衰と停止の混同**：減衰 0.7 だと2回目の候補は構造的に上位に入れない。減衰を近さ P だけに掛けるか、回ごとに上位を比べる形に直す（検証レポート §3.1）。
- **研究の少ない遺伝子**：どの近さでも見つけにくい。社内オミクスデータを別の入力として足す以外に補えない。
- **正解ラベルの偏り**：承認薬の標的は「生物学的に正しいもの」ではなく「製薬会社が選んだもの」。
- **遺伝子セットの正解・可能性は現状 Claude の知識で作った未検証の表**。Mac から Open Targets に届けば `--opentargets` で置き換える。

## 6. 進め方

1. Mac で set100 を TxGemma に採点させ、Claude の判定との相関を見る（質問文の見直し）。
2. set100 でループを回し、既知の再現と可能性遺伝子の位置をランダム基準線と比べる。
3. 減衰の掛け方を決めてルールを固定する。
4. set1000 → 全遺伝子へ。複数モデルの平均。
5. 統合失調症で同じ手順を回し、病気を変えても仕組みが壊れないかを確かめる。
6. 時間で区切るテスト。
7. 上位の仮説カードから実験へ。

## 7. 30年後から見て残るもの

AI は「文献を圧縮したもの」として毎年入れ替わる。残る財産は、**病気の部品表と質問セット（引き出し方）、しくみの鎖（専門家の判断）、遺伝子セットと時間で区切るテスト（測り方）**。このリポジトリは、その3つをコードと表として持つための土台である。
